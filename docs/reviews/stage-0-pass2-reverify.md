## A. Native-import gate: what I tried (original finding 1)

I generated 30 spellings of an attribute list and compared the lint with the compiler (identifier tokens whose value text is `LibraryImport`/`DllImport`, with or without `Attribute`). `NativeImports` never counted fewer than the compiler for: plain, `System.Runtime.InteropServices.` qualified, `global::` qualified, alias-qualified, `...Attribute`, verbatim identifier, Unicode-escaped identifier, `[method: ...]` target, `[SuppressGCTransition, LibraryImport(...)]` list, newline-separated arguments, `using` alias, constants as first or EntryPoint argument, concatenated and verbatim/raw/interpolated/escaped literals, `typeof(...)`, `[` and a `(` char literal inside the arguments, `#if` inside the arguments, `DllImport`, `DllImportAttribute`. Every one of those either parses to a plain literal pair (and is then checked against the approved list) or is counted as unreadable (which the test rejects). The only miss is R1.

## B. Scanner and scope (original findings 2, 3): what I tried

- **Differential fuzz against the compiler.** 120,000 random but compilable programs (three seeds of 40,000) mixing comments, strings (regular, verbatim, interpolated, raw, nested holes), char literals including a quote, all five line-end kinds (CR, LF, CRLF, U+0085, U+2028, U+2029), `#region` / `#if` / `#pragma` / `#nullable` lines with stray quotes and apostrophes. Check: every identifier or keyword the compiler sees must be a word in the scanner's code view, and the scanner must end in code. Result: **0 mismatches**. (An earlier run with my generator producing unbalanced `#region` lines gave 75 percent invalid programs and also 0 mismatches.)
- The Unicode-escape decoding works for identifiers and strings; the `Repo.AllFiles` rule matches the SDK (`bin`/`obj` only directly inside a project directory) and a `Probes/bin/X.cs` file is now scanned. Remaining scope holes are in R2.
- An explicit `<Compile Include="bin\Evil.cs" />` of a file in the project's own `bin` folder is not scanned by the text lints, but the analyzer catches a plain violation in it (RS0030); not a finding on its own.

## D. What I verified is correct

- Dispositions 2, 5, 6, 7, 10, 11, 12, 14 and the interim items are as claimed (code read, tests read, mutations above). `anticheat.state` on this PC is now `Unknown` ("game-session status unknown (no game-session detector yet)"), `mode.optimize` lists every unknown input, the "none" rows read "none of the N catalogued ..." and are `Inferred`, a positive finding stays `Measured`.
- `AntiCheatSafety`: `Unknown` (value 4) is safe mode, `Decide` suppresses the restricted classes for it and ignores a per-game override for it; allow-listed collectors are never suppressed; a known protected title or game session stands whatever else is unknown; incomplete inputs can only make the state more restrictive.
- `IScmNative` seam: `OpenService` captures the Win32 error immediately after the call; every opened handle is closed (balance asserted on success, each error class, and manager failure); access masks asserted as 0x0001 and 0x0004; the pure mappers are table-tested.
- `EtwNative.DecodeName` / `ReadName` bound the read to the slot and treat "no terminator" as unreadable; the `whileRunning` hook runs while the session is live and the session is stopped in a `finally` even if the hook throws (positive-control tests ran on this PC, nothing skipped).
- `OsProbe.Support`: unreadable `InstallationType` is Unknown; non-Client is unsupported; S mode unsupported; build thresholds right; S mode Unknown does not by itself make Windows unsupported (the S-mode row blocks instead). `HardwareProbe.FormFactor`: an empty chassis list is Unknown.
- `CheckManaged`: a value that is neither the blocking constant nor a listed clean constant blocks ("state unrecognized"); missing or non-Available rows block.
- The smoke gate fails on a failed probe, a missing probe, too few rows and an empty matrix, and its self-test can fail (mutation). `build.ps1` runs the coverage proof and the gate self-test before the smoke step and `Invoke-Step` stops on a non-zero exit code.
- `tools/dev/analyzer-coverage`: 83 entries, 86 proof lines, one diagnostic per line, 11 allowed controls clean.
- The product code itself still contains no banned call: the 11 approved imports are the only imports, the only `Process` use is the name-only snapshot behind the pinned pragma.

## E. What I could NOT check

- Anything in an elevated token, a 32-bit process, a real S-mode / domain-joined / MDM-enrolled / Entra-joined device, a real game session, or a service whose security descriptor denies `SERVICE_QUERY_STATUS` (as in pass 2). Whether `QueryAllTraces` hides sessions from a non-elevated caller is still unverified.
- The behaviour of the analyzer package on generated code beyond what the probe project showed (it did not flag `DllImportAttribute` emitted by the LibraryImport generator, which is why the implementer left it unbanned; I did not build a counter-example).
- Whether Roslyn treats `/* c */ #region` (a directive after a block comment on the same line) as a directive; the scanner treats it as one, which can only hide more code from the lint if the compiler disagrees - the fuzz did not generate this form.
- `docs/LIMITATIONS.md` L17-L19 and `docs/FACTS.md` F29/F30 were not re-read for accuracy.
