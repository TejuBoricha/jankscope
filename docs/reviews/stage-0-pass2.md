Reviewer: an independent read-only session with fresh context (2026-10-16). It did not take the status column of `docs/reviews/stage-0.md` on trust and re-derived each claim from the code. Scope: `src/`, `tools/`, `tests/`, `build.ps1`, `Directory.*.props`, `.editorconfig`.

**Working method.** The implementing session was editing the live tree during this review (BannedApiAnalyzers, `Directory.Build.targets`, `BannedSymbols.txt`, `RepoLintTests.cs`, `build.ps1`, `ServiceState.cs` pragmas). To avoid interfering, every experiment (evasion plants, mutation checks, an offline-restore simulation) ran in a private copy of the tree taken before those edits (when compared at about 13:16 IST, all of `src/` and `tests/` were byte-identical to the live tree except `RepoLintTests.cs`), with the in-flux analyzer files removed from the copy. **Result: 0 Critical, 1 High, 7 Medium, 6 Low.** Gate rule (spec section 1 #4): **Stage 0 must not be marked `done-verified` while finding 1 is open.** The product code itself contains no banned call today (checked by reading every `.cs` file in `src/` and `tools/`: the only `Process` use is the name-only snapshot, the native imports are exactly the 11 approved ones). ## What I verified is correct

- **`EtwNative` layout and arithmetic (x64/ARM64).** Offsets 0 (Wnode.BufferSize), 24 (Guid), 40 (ClientContext), 44 (Flags), 64 (LogFileMode), 112 (LogFileNameOffset), 116 (LoggerNameOffset), total 120, are right for `EVENT_TRACE_PROPERTIES` with an 8-byte `HANDLE` (checked against the header layout and by the bench: 39 sessions decode on this PC). `QueryBufferBytes` = 120 + 2 x 1024 x 2 = 4216, a multiple of 8, so every record is aligned. `Wnode.BufferSize` equals each record size, so the system cannot write past a record. `TryOpenAndCloseRealTimeSession` allocates `120 + (len + 1) x 2` and the name copy (len chars) plus terminator fits exactly; `LogFileNameOffset = 0` is valid for a real-time-only session; `Guid.TryWriteBytes` writes the Windows in-memory GUID layout.
- **Allocation and cleanup.** `AllocZeroed` blocks are freed in `finally` on every path (success, ERROR_MORE_DATA retry, error status, exception after allocation); the allocation call itself throws on failure, so there is nothing to leak before the `try`. The retry loop is bounded (two attempts, capacity capped at 1024), never trusts `needed` beyond the cap, and fails closed with `ERROR_MORE_DATA` and no names. Loop bounds `i < count && i < capacity` and the `offset` range check (`>= 120`, `<= size - 2`) are correct; an unreadable name is counted as an empty string.
- **32-bit guard.** `LayoutSupported` is `nint.Size == 8`; both entry points return `ERROR_NOT_SUPPORTED` before touching memory. (Only the logic is tested; no 32-bit process was run.)
- **`ScmServiceStateReader`.** Rights are `SC_MANAGER_CONNECT` and `SERVICE_QUERY_STATUS` only; both handles are closed in nested `finally`; `GetLastPInvokeError` is read immediately after `OpenService`; 1060 and 123 map to NotInstalled and every other failure (including access denied) to Unknown; `SERVICE_STATUS_PROCESS` is 9 x DWORD = 36 bytes; states 2-7 count as Running (conservative); names containing `/` or `\`, empty, or longer than 256 are refused before the registry path is built. Bench: `vgk` Installed/Running/start 1, `vgc` and `EasyAntiCheat_EOS` Installed/Stopped/start 3, `EasyAntiCheat`, `BEService`, `BEDaisy` NotInstalled, `RpcSs` Running.
- **`AntiCheatProbe` decision table.** Resident wins over Unknown; Unknown services and a missing process snapshot (when the entry has helper processes) make the entry Undetermined, which makes `resident`, `installed_not_running` and `state` Unknown, never none/Idle; the process snapshot being null makes `protected_running` Unknown; both catalogs missing, or only the anti-cheat one, give Unknown; a known protected title keeps safe mode whatever else is unknown (a gap cannot weaken a state that is already restrictive). All four `anticheat.*` rows are always emitted by the probe. (The one real hole in the state is finding 5.)
- **`CapabilityMatrixBuilder`.** A probe that exceeds the timeout is abandoned on a thread-pool thread (a background thread; it cannot keep the process alive), its late result is discarded, its failure is exported by exception type only, `TimeoutException` thrown by a probe is not confused with a timeout, and one stuck probe cannot stop the others. `frame.capture`: an elevated or unknown-elevation probe yields Unknown, only a definite non-elevated token yields `NeedsOptionalTool`, `NeedsUserAction` only for access denied. `mode.optimize`: every input that is missing or not `Available` blocks, `os.support` NotAvailable gives "unsupported Windows", the planned VM row blocks (this PC: "Recommend-only: virtual-machine state unknown"). Unknown never becomes eligible in the current code paths.
- **`SystemProbes`.** `Reg.ReadInt` is tri-state (absent key or value = Absent; wrong type or access error = Unreadable); S mode, Smart App Control, Secure Boot and HVCI map unrecognised values to Unknown; `BatteryPresence` handles 255, 128 and the bitmask correctly; the chassis table matches the documented SMBIOS values 1-24 and 30-32; `SYSTEM_POWER_STATUS` and `SERVICE_STATUS_PROCESS` struct layouts and the `IsDeviceRegisteredWithManagement` / `NetGetJoinInformation` signatures match the headers; `NetApiBufferFree` is called whenever a buffer is returned; the 256-char UPN buffer is freed in `finally`.
- **Lint engine, positive behaviour.** Comment and string handling, verbatim/interpolated/raw strings with nested holes, char literals containing quotes, literal concatenation joining and the vendor word-splitting all behave as the engine tests say (and as my own samples C0-C3 and the CRLF/non-region controls confirm). `DefaultDllImportSearchPaths(System32)` is on the assembly and `AllowUnsafeBlocks` is only in `Jankscope.Platform`. The exact approved import set currently equals the 11 imports in `Native.cs`.
- **Other.** `tools/fetch-third-party.ps1` verifies size and SHA-256 and deletes on mismatch (path traversal through a malicious lock file is theoretical: lock files are repo content). `tools/dev/apply-edits.js` is a dev-only text editor. `.gitattributes`/`.editorconfig` are coherent; `build.ps1` is PowerShell 5.1-safe.
