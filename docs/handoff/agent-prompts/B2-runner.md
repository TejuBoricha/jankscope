REQUIREMENTS (the runner launches a pinned, hash-verified third-party console exe):
1. `PresentMonArguments.Build(...)` returns an ordered `IReadOnlyList<string>` argv — NEVER a joined command-line string: `--output_stdout --no_console_stats --session_name <name> [--process_name <exe> …] [--terminate_on_proc_exit] [--timed N --terminate_after_timed]`. The session name must start with `Jankscope.Core.Branding.EtwSessionPrefix` or Build throws. Process names must be plain exe names: reject path separators, quotes, control characters and a leading `-`; names with spaces, `&`, `;` or unicode stay ONE argv element (argument-injection tests). NEVER emit `--restart_as_admin` (it would self-elevate; the pinned binary does have this option). Emit `--stop_existing_session` / `--terminate_existing_session` only when explicitly requested AND the session name carries our prefix.
2. `FileHashVerifier` verifies size + SHA-256 of the executable before EVERY launch. Compute the hash on the exact file that is then launched; mitigate TOCTOU by holding the file open with `FileShare.Read` across the launch where Windows allows — document the residual risk honestly. The path must be absolute, exist and be a regular file (no PATH lookup, no relative paths); mismatch → refuse with an explicit reason.
3. `IProcessLauncher` abstraction + `PresentMonProcessLauncher`, the ONLY product file allowed to use `ProcessStartInfo`/`Process` (UseShellExecute=false, ArgumentList, RedirectStandardOutput/Error, CreateNoWindow, minimal environment, working directory = a temp dir you control). Provide an in-memory fake launcher for unit tests.
4. `PresentMonRunner`: reads stdout lines asynchronously and feeds an `IFrameLogParser`; exposes samples via a bounded channel with a defined and tested back-pressure policy (drop-oldest or block — choose, justify, count dropped); a watchdog (no output for `WatchdogNoOutputTimeout` → kill + health "stalled"; drive it with `TimeProvider` so tests are fast); one-click Stop (cancellation → graceful, then kill the process tree you started after a grace period); crash handling with bounded restarts + exponential back-off + `RunnerHealth` (state, restarts, lastError, linesRead, rowsParsed, problems, droppedFrames); stderr captured (PresentMon prints a warning that short-running/other-account processes appear as `<unknown>` when unelevated — surface it as a note, not an error); guaranteed cleanup (no orphan child process, no leaked ETW session).
5. The fake exe: prints a PresentMon 2.6.0-style header and rows (copy the header and a few rows from `tests/fixtures/presentmon/v2.6.0-real-sanitized.csv`) to stdout; supports modes (normal N rows, hang, crash with an exit code, slow output, unknown-args tolerant); records its argv to a file so tests can assert exactly what was passed.
6. A real-binary integration test tagged `[Trait("requires","presentmon")]` that runs the pinned `third_party/PresentMon/2.6.0/PresentMon-2.6.0-x64.exe` for ~3 seconds, unelevated, with our session prefix and `--timed`, then asserts rows arrived (trivial ad-hoc parsing), no process remains, and `logman query -ets` shows no session with our prefix. It must SKIP WITH A REASON (write your own conditional Fact attribute that sets `Skip`; no extra packages) when the binary is missing or the machine cannot open a real-time ETW session. Size and hash come from the lock file.

TESTS ALSO COVER: argument-injection cases, hash-mismatch refusal, relative-path refusal, watchdog, crash/restart/back-off math, bounded back-pressure, session-prefix enforcement, `--restart_as_admin` never emitted (with a mutation check), cleanup after cancellation.
