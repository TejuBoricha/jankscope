# Independent code review — Stage 0

Reviewer: a separate read-only sub-agent with fresh context (2026-10-16, ~14 minutes, 51 tool calls). Scope: `src/`, `tools/`, `tests/`, `catalogs/`, `build.ps1`, `Directory.*.props`. It ran only `build`/`test --no-restore` and scratch F# scripts outside the repo; it did **not** run the Platform tests or the CLI (both open a real ETW session). Findings below are the reviewer's, each re-checked by the integrator; dispositions are the integrator's.

**Gate rule (spec §1 #4):** no stage is `done-verified` while a Critical or High finding is open. Stage 0 had one High (#1, fixed). Medium findings were worked in three batches (below). **Stage 0 stays open until the independent re-review of the fixes (second pass) has run** — the fixes were verified by tests, mutation checks and a bench run, but their author cannot also be their independent reviewer.

## Process notes
- A mutation check of fix #1 caused a **self-inflicted encoding bug** (Windows PowerShell 5.1 `Get-Content` re-read UTF-8 as ANSI and wrote mojibake into `FrameStats.cs`); it was caught by a file-change notice, the file was rewritten from known content, and the repo was scanned for mojibake (clean). Lesson recorded in `HANDOFF.md`.
- **A second encoding incident, caught by the new lint the same day:** the file-writing tool turned `\uXXXX` escape sequences in text it was given into literal characters, so a test source contained a literal U+FFFD and mojibake characters and flagged itself. Fixed by building those values from numeric char codes (`(char)0xFFFD`), so the source stays ASCII. Lesson: do not put `\u` escapes in text passed to the write tool; use `(char)0x…` or verify with `od -c`.
- Parallel Stage 1a agents were launched mid-review in private copies and then stopped on the owner's request; nothing from them was merged (see `HANDOFF.md`).
