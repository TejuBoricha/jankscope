# Jankscope GUI run on a real Windows machine (signal theme, Release build, 2026-11-12)

Machine: Windows 11 26300, 1920x1080 at 125% (DPI 120), PerMonitorV2. App launched, no crash, always Responding.
Method: UIA select/invoke + PrintWindow. Simulated trace used for Watch/Replay (Simulate 120 FPS Stutter Trace). Real input used for the Input lab (cursor orbit).
Cleanup: app quit via tray menu "Quit (stops capturing)"; the settings file was restored and no process remained.

## What worked
- No crash, no hang, all 6 pages render in Dark and Light. Theme switch (Settings, then Apply & Save) re-themes the whole app live; settings.json was written (theme Light) and restored afterwards.
- Capability check is REAL data: Windows 11 build 26300.9818, CoreSingleLanguage, 40 of 64 ETW sessions, Riot Vanguard resident, EAC stopped, GPU counters 579/592 readable. 41 rows / 36 ready / 5 needs attention, consistent with the CLI probe. Filters (All/Ready/Needs attention) work.
- Trust page system summary is real (same Vanguard/ETW facts).
- Watch with no target: Start does nothing harmful, shows amber "A process name is empty." next to "Not capturing"; nothing crashes. KPIs stay "--".
- Input lab is real: orbiting the cursor produced 72 Hz / 14.0 ms median / 7.2 ms jitter and a live trail + arrival spectrum (these numbers came from my scripted cursor, not meaningful hardware data).
- Window minimum size is enforced (800x500 request clamped to 1275x875 px = 1020x700 DIP). Closing the window hides to tray (process stays). Tray menu: Open Jankscope restores the window; Quit (stops capturing) exits the process cleanly.
- Watch, Replay values after Simulate are FIXTURE data and are labelled "PROVENANCE: SIMULATED DEMO" in the top bar. Good. (Replay's hypothesis card "Resident kernel anti-cheat presence / Riot Vanguard" is REAL machine data mixed into a simulated mark.)

## Status of these findings (added when this report was committed)

- Defect 2 (dark-theme primary button contrast) was fixed in the signal-theme PR: the app-wide TextBlock style overrode the button's foreground.
- Defect 3 (the "8313 ms" jitter figure) was not a unit bug. The built-in demo wrote 2,400 frames (about 20 s of capture time) in an instant, and the capture clock map correctly read that as seconds of delivery jitter; the same wrong figure also drew an equally wide uncertainty band on the Replay timeline. Fixed at the source: the simulator now states when each frame arrived (history stamped as if it had arrived on schedule, live frames paced against the clock), through an optional `ArrivalTicks` on `CapturedFrame` that a live capture never sets. Reverting the stamping reproduces the report (8343.7 ms in `SimulatedFrameSourceTests`).
- Defect 1, the cause: the hypothesis title sat in a row that never wrapped, so any long title clipped at every window size. It now wraps beside the grade badge (`A_long_cause_title_wraps_inside_its_card_instead_of_being_cut_off`; with `NoWrap` the title ran 302 px past the list edge). The other minimum-size collisions listed under defect 1 (KPI labels, timeline header, spike anatomy and pacing tiers) are still open.
- Fixed in the copy and capability-check change: 7 (the Trust sentence about links is shown only when a link is), 10 (the step banner names the real Replay page, no longer hard-codes a hotkey, and has the full text in a tooltip), 11 (the Watch idle text names the real button), 13 (plain-word badges, "needs setup" counts only what the person could set up, a note for the rest, the anti-cheat card shows the state reached, and an unreadable state says Unknown instead of "Passive / Clear"), 14 (list items announce readable text to a screen reader) and the contrast part of 8 (light-theme warning text is now about 6:1 on the cream, was about 4.6:1). The ellipsis in 8 is part of the Replay minimum-size layout work and is still open.
- Fixed in the page-scaling change: 1 (the rest), 4, 5, 6, 12, the unreadable header sentences of 3 and 8, and the layout shift of 15. Cause of the minimum-size collisions: the pages were arranged for about 1040 by 700 and squeezed below that. They are now laid out for that design size and scaled down together in a smaller window (`PageScaling`; the smallest window the program allows scales to about 0.76), so labels never collide and nothing needs scrolling. Separately: the Watch status strip is now a status line over a controls line (the headline was cut by the target box even at 1280 wide), the Replay header's long sentences wrap beside the export button instead of being trimmed to "...about 8...", and the placeholder messages and the spike-anatomy headers in the custom-drawn views stay inside their width.
- Also fixed: 16 (the tray tooltip drops the hotkey list before Windows cuts it at 63 characters, so the headline stays whole) and 17 (the window opens no larger than the usable screen area, never below its minimum). The "reopened full-size after hide and show" part of 17 could not be tied to code: showing the window never resets its size. It stays unverified.
- 9 (the native title bar is white in the dark theme) was held back because it needs the `DwmSetWindowAttribute` native import, and every native import needs an entry in `RepoLintTests.ApprovedLibraryImports` and an independent review. The owner approved it on 2026-11-13; it is fixed in the dark-title-bar change: one new import (`dwmapi.dll!DwmSetWindowAttribute`, attribute 20 only) in `Jankscope.Platform/Windowing/TitleBar.cs`, and `TitleBarTheme` in the app styles each window when its handle exists and restyles the open ones when the theme changes (fact F35). Run on the real app: the attribute reads back 1 on the main window and the title bar and caption buttons are drawn dark. 12 (spike-anatomy header overlap) is fixed above.
- Fixed in the wording change (the rest of 15): the Watch stutter tile says "3 single, 1 burst of 3" instead of "3 isolated | 4 cluster(s)" (the parts add up to the stutter count, and the status line spells it out: "6 stutter(s) in the last 30 s: 3 single spikes, 1 burst of 3"); the Replay tile says "4 clusters" (and "1 cluster"), never "cluster(s)"; the grey band that "no frames logged" was drawn on says "before the first frame" when it is the part of the 30 s view that predates the capture (and "after the last frame" at the other end), and keeps "no frames logged" for a real hole between frames. The watermark is drawn only where it fits inside the band, and the cursor text follows the same three cases. The Replay tier labels carry their unit once: the narrow heading is "TIERS (ms)" and the five labels no longer mix "ms" on the two ends with none in the middle ("16.7-33" is now "16.7-33.3"). A new find in the same render: the Replay time-axis label "key press" under the newest end was cut to "key pr"; axis labels now move left to stay inside the view. All of it is covered by tests (`StutterWordingTests`, `FrameDistributionLabelTests`, three in `TimelineViewTests`); the renders were looked at (`window-capture-simulated`, `window-investigator-simulated`).
- Everything else is open: the rest of 8 (the ellipsis in the Replay warning line), the disabled-button contrast in 14, and the unverified second half of 17.
- Not tested in this run: real frame capture (the capture tool is not bundled), the export and preview dialogs, hotkey presses, Scan 3D, the welcome dialog.
