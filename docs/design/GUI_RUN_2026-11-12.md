# Jankscope GUI run on a real Windows machine (signal theme, Release build, 2026-11-12)

Machine: Windows 11 26300, 1920x1080 at 125% (DPI 120), PerMonitorV2. App launched, no crash, always Responding.
Method: UIA select/invoke + PrintWindow. Simulated trace used for Watch/Replay (Simulate 120 FPS Stutter Trace). Real input used for the Input lab (cursor orbit).
Cleanup: app quit via tray menu "Quit (stops capturing)"; the settings file was restored and no process remained.

## What worked
- No crash, no hang, all 6 pages render in Dark and Light. Theme switch (Settings, then Apply & Save) re-themes the whole app live; settings.json was written (theme Light) and restored afterwards.
- Capability check is REAL data: Windows 11 build 26300.9818, CoreSingleLanguage, 40 of 64 ETW sessions, Riot Vanguard resident, EAC stopped, GPU counters 579/592 readable. 41 rows / 36 ready / 5 needs attention, consistent with the CLI probe. Filters (All/Ready/Needs attention) work.
- Trust page system summary is real (same Vanguard/ETW facts).
- Watch with no target: Start does nothing harmful, shows amber "A process name is empty." next to "Not capturing"; nothing crashes. KPIs stay "--".
- Input lab is real: orbiting the cursor produced 72 Hz / 14.0 ms median / 7.2 ms jitter and a live trail + arrival spectrum (these numbers came from my scripted cursor, not meaningful hardware data).
- Window minimum size is enforced (800x500 request clamped to 1275x875 px = 1020x700 DIP). Closing the window hides to tray (process stays). Tray menu: Open Jankscope restores the window; Quit (stops capturing) exits the process cleanly.
- Watch, Replay values after Simulate are FIXTURE data and are labelled "PROVENANCE: SIMULATED DEMO" in the top bar. Good. (Replay's hypothesis card "Resident kernel anti-cheat presence / Riot Vanguard" is REAL machine data mixed into a simulated mark.)

Hypothesis title clipped to "Frame pacing h" (this is the reported "Frame pacing hitc..." cut-off, reproduced; no wrap/trim). Screens 10, 25.
   At the default/large size the card title "Frame pacing hitch" fits, but a longer title still clips: "Resident kernel anti-cheat presenc" (Light, 1280 DIP wide, screen 20) - so the root cause is the unwrapped TextBlock in the hypothesis card, not just min size.
2. Dark theme, primary buttons: lime-filled buttons (Start, Mark stutter, Export Redacted Compatibility Report..., Apply & Save Configuration) have pale-green text on lime, contrast is very poor (screens 01, 03, 05, 06, 08). Light theme uses dark green fill with dark/white text and is readable.

## DPI (125%)
Rendered crisp, no blur, no mis-scaled controls. System DPI 120 reported for the window. No per-page scaling bugs seen apart from the size overflow in item 17.

## Status of these findings (added when this report was committed)

- Defect 2 (dark-theme primary button contrast) was fixed in the signal-theme PR: the app-wide TextBlock style overrode the button's foreground.
- Everything else is open. Defect 1 (Replay clipping at minimum size) and defect 3 (the "8313 ms" jitter figure, a likely unit bug in the header text) are the first to look at in phase 2.
- Not tested in this run: real frame capture (the capture tool is not bundled), the export and preview dialogs, hotkey presses, Scan 3D, the welcome dialog.
