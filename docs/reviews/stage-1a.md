# Independent code review - Stage 1a (headless core)

Reviewer: an independent read-only session with fresh context (started 2026-10-17, finished 2026-10-18). It did not take `STATUS.md`, `CONTEXT.md`, the hand-over notes or the authors' test counts on trust; every finding below was re-derived from the code and, where the finding is about behaviour, reproduced with an experiment. Scope: the five merged work packages (A ring buffer and detector, B1 CSV parser, B2 runner, C hardware/PDH/VM, D harness) and their integration seams (`DefaultProbes`, `PlannedProbe`, `Assert-ProbeMatrix`, the catalog loader, the `RepoLintTests` lists).

**Working method.** The real repository was only read. Every experiment (plants, mutations, fuzzing, concurrent test runs, real-binary runs) ran in a private copy outside the repo (`C:\Users\tejas\Desktop\PC FPS booster - review1a`, made with robocopy without bin, obj and .git, with `third_party` kept so the real PresentMon tests could run). No network, no install, no download, no commit. The only file written inside the repo is this one. Two real-binary experiments started and ended PresentMon sessions with names that start with `Jankscope-rv`; all were removed again (checked with `logman query -ets`).

**Baseline (private copy, the code under review):** `build.ps1` green: 0 warnings, 654 Core + 973 Frames (1 skipped) + 118 Harness + 309 Platform = 2,054 tests, smoke "41 capability rows, 13 probes, 0 failed". This matches `CONTEXT.md`.

Severity legend (as in the Stage 0 reviews): **High** = a hard constraint's guarantee is false or fails open under realistic input, silently. **Medium** = a safety property is unguarded, a guard has a confirmed bypass, or a documented claim is wrong, with no present harm. **Low** = hardening, wording, test hygiene.

## Result: 0 Critical, 1 High, 7 Medium, 13 Low

**Gate statement: Stage 1a must NOT be marked `done-verified` while finding 1 (High) is open.** No Critical finding. ## What I verified is correct

- **Argument grammar (B2).** `PresentMonArguments.EnsureSafe` is an allowlist, not a denylist; a value slot cannot smuggle an option (the next element must satisfy the value grammar); session names need the exact ordinal prefix; `--stop_existing_session` is never produced by the runner; the terminate form carries exactly its three elements.
- **Environment, working directory, input** of the child: only `SystemRoot`, `windir`, `SystemDrive`, `PATH` (System32), `TEMP`, `TMP`; a private `Jankscope-pm-*` directory removed on release; stdin closed (authors' tests read and judged sound).
- **Hash and size verification** is done on the handle that stays open across the verification, size before hash, fixed-time comparison, permanent versus transient outcomes distinguished, and repeated before every launch including the session-ending helper (mutation R7 killed).
- **Canonical path rule** (X7): ADS, trailing dot or blank, `..`, forward slashes, verbatim and device prefixes, doubled backslashes refused.
- **Output reading.** `BoundedLineReader` caps a line at 16 K characters, handles split UTF-8, LF and CRLF, lone CR as data, invalid bytes as U+FFFD; the queue is bounded, drops the oldest frame, counts it, and never blocks the reader (mutation R15 killed).
- **RingBuffer memory model.** Per-slot seqlock re-derived: claim (release store plus full fence) before the slot write, commit (release) after, reader acquire read of the commit, copy, full fence, `claimed` re-read, items `j < claimed - Capacity` cut from the front. Correct for x64 and ARM64 as argued; capacity 1, wrap-around, overlapping move, the CAS single-writer guard and `long` counters are fine. The write path has no allocation site. The only unproven part is the reader fence (finding in the mutation table).
- **SlidingMedian** (two indexed heaps): insertion side with `<=`, rebalancing invariant, middle removal (`SiftUp` then `SiftDown` at the entry's new index), growth and clear, overflow-safe even-count median.
- **CSV parser (B1).** Columns by name, case-insensitive, any order; duplicates and conflicting clocks make the log unsupported with a reason; `NA` and empty are null, never zero; numbers parsed with the invariant culture; every cell of a column the parser reads must be valid or the row is rejected; length caps. Streaming memory is bounded for the lazy path (`TextReader.ReadLine` itself is unbounded before the 16 K check: Low, file path only).
- **Native layouts and imports (C).** Checked against the documented headers: `DISPLAYCONFIG_PATH_INFO` 72 bytes with the used offsets, `DISPLAYCONFIG_MODE_INFO` 64, the advanced-colour request 32 bytes with `size` equal to the buffer length (no over-write), `PROCESSOR_RELATIONSHIP` and `CACHE_RELATIONSHIP` offsets, `GROUP_AFFINITY` 16, `PDH_FMT_COUNTERVALUE_ITEM_W` 24 with every pointer range-checked inside the allocation, PDH format flags and `PDH_MORE_DATA`. Retry loops are bounded and free their buffers in `finally`. LUID composition: Vortice's `Luid` is `LowPart uint`, `HighPart int` (read by reflection), so `(long)High << 32 | Low` is right, and the display path and PDH parsers use the same word order.
- **System32-only for DXGI.** `CreateDXGIFactory1` is imported by `Jankscope.Platform` itself (covered by the assembly attribute); Vortice's own `DXGI.CreateDXGIFactory1` imports `dxgi.dll` without it, and `DxgiAdapterSource` does not call it (a text test pins that one file). The harness does use Vortice's imports (default search path); it is a development tool, not shipped.
- **GPU-wake claim.** The source guard is real (no device creation, no output enumeration in `DxgiAdapterSource`; PDH only), and `jankscope probe` listed the NVIDIA adapter as "drives no active display" without a device. Whether DXGI enumeration alone wakes a sleeping GPU was not measured (the bench GPU was already awake).
- **Catalog loader.** Fail-closed (any invalid file, including a missing `vm_markers.json`, makes `CatalogSet.Load` throw `InvalidDataException`; the same call also loses the anti-cheat and protected-title catalogs, the safe direction); markers at least 3 characters and plain names; control characters rejected in free text.
- **Integration seams.** `DefaultProbes` contains the five new probes; the four Planned rows they replace are gone from `PlannedProbe` (a test pins it); `Assert-ProbeMatrix` lists the new probe ids; `ApprovedLibraryImports` lists exactly the 22 imports in the code.
- **Honesty of numbers in the docs:** the verified counts in `CONTEXT.md` (2,054 tests, 41 rows, 13 probes) reproduce.
