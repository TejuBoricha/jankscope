Use Vortice.DXGI for adapters: `GeneratedComInterface`, `ComImport` and `ComWrappers` are banned by the analyzer, so hand-written COM is not an option.

REQUIREMENTS (probes implement `IProbe`, return `CapabilityEntry` rows with source + reason; they REPLACE the NotImplemented rows `gpu.adapters`, `cpu.topology`, `display.topology`, `environment.virtual_machine`):
1. CPU topology: `GetLogicalProcessorInformationEx` (RelationProcessorCore with EfficiencyClass and SMT flags; RelationCache/L3 groups for multi-CCD) and/or `GetSystemCpuSetInformation`. A PURE mapper from raw records to `CpuTopology` (logical count, physical cores, performance vs efficiency counts, SMT on/off, cache-group count) with fixtures: hybrid 6P+8E (the reference bench is 6 SMT performance cores + 4 efficiency cores = 10 cores / 16 threads; the 6P+8E fixture is synthetic), non-hybrid with SMT, SMT off, multi-L3. Real-machine test: performance + efficiency logical counts sum to the logical processor count.
2. GPU adapters keyed by LUID (never by index): LUID, description, numeric vendor/device ids, dedicated/shared memory, software flag; which adapter drives each output. Report facts as DATA; do not draw conclusions like "game on iGPU" here.
3. Displays: per-monitor refresh rate via `QueryDisplayConfig` (documented CCD API), mixed-refresh detection; VRR/HDR only if documented and obtainable, else explicit "not available (reason)".
4. PDH sampler: `PdhOpenQuery` + `PdhAddEnglishCounterW` (English paths on any locale) + `PdhCollectQueryData` + formatted array reads. Counters: CPU total and per-core utilization (`\Processor Information(*)\% Processor Utility` or documented equivalent), effective frequency if available, memory available/committed, hard faults (`\Memory\Pages Input/sec`), disk latency/queue (`\PhysicalDisk(*)\Avg. Disk sec/Transfer`, `Current Disk Queue Length`), GPU engine utilization (`\GPU Engine(*)\Utilization Percentage`), GPU adapter memory (`\GPU Adapter Memory(*)\Dedicated Usage`/`Shared Usage`). PURE parser for GPU Engine instance names `pid_<n>_luid_0x<hi>_0x<lo>_phys_<n>_eng_<n>_engtype_<name>` with fixtures captured on THIS machine (a hybrid laptop: two LUIDs), pids sanitised; aggregate per LUID and per engine type. A missing counter/instance yields an explicit "not available (reason)" sample, never 0. Sampling at 1–10 Hz on a dedicated timer with a drift test and a measured self-cost (CPU time over 10 s — report it). Do NOT wake sleeping GPUs: PDH only, no vendor API (spec §7.2).
5. VM detection is catalog-driven (`catalogs/vm_markers.json`; entries you can justify as documented/community, honest verification level, sources) matched against documented firmware/WMI strings; no vendor names in code. **Convention for the integrator:** an Available `environment.virtual_machine` row must use `ManagedValues.VmNone` ("not a virtual machine") or `ManagedValues.VmPrefix` + the catalog display name ("virtual machine: <name>"), exactly; anything else blocks `mode.optimize`. Test that your probe's own output passes `ManagedValues.IsKnownVirtualMachineValue`.
6. Do not edit `CapabilityMatrixBuilder.cs`; report the exact lines for `DefaultProbes.Create` and which Planned rows to remove.
Real-machine tests must be STRUCTURAL (no assertions about a specific GPU/CPU model, vendor or core count) and must pass when run by a non-elevated user and on machines without a battery or GPU counters.
